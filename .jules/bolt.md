## 2024-05-15 - [N+1 Query Optimization in Enrollments Iteration]
**Learning:** In Open edX, iterating over user enrollments using `CourseEnrollment.enrollments_for_user(user)` and subsequently accessing `enrollment.course_overview` causes an N+1 query problem, as `course_overview` is loaded lazily for each enrollment. Using `enrollments_for_user_with_overviews_preload` evaluates the queryset and returns a python list, preventing the use of chained query methods like `.order_by()`.
**Action:** When accessing `course_overview` properties on enrollments retrieved for a user, chain `.select_related('course')` to the original QuerySet. This performs a SQL JOIN to eager load the course (which represents the `CourseOverview` via a ForeignKey relationship), safely bypassing the N+1 issue without breaking query composability.
