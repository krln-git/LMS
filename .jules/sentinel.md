## 2024-05-18 - Fix SQL Injection in Email Opt-in List Command
**Vulnerability:** The `email_opt_in_list` management command used string interpolation (`.format()`) to build a raw SQL query with lists of `course_id` and `org` aliases. This bypassed parameterized query protection, allowing a malicious org alias or course ID to inject arbitrary SQL statements and potentially extract or modify sensitive user data from the database.
**Learning:** Even internal management commands and background jobs need strict parameterized queries when accepting dynamic input (like org lists passed via CLI or APIs). Custom serialization functions like `_sql_list` that wrap strings in quotes are insufficient and dangerous compared to native database driver parameters.
**Prevention:** Never use string formatting (`.format()` or `%`) to insert data into SQL queries. Always use `%s` placeholders and pass the variables as a tuple/list to the `params` argument in `cursor.execute()`. For `IN` clauses with dynamic lists, dynamically generate the correct number of `%s` placeholders (e.g., `",".join(["%s"] * len(values))`) and pass the flattened list of variables.
