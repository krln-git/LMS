## 2026-02-26 - [Misleading "Double Escaping" Justification]
**Vulnerability:** Found `|safe` used inside a JavaScript string literal (`"{{ message|safe }}"`), creating an XSS vulnerability. The code had a misleading comment claiming `|safe` was necessary to prevent "double escaping" because the data would later be rendered by React.
**Learning:** Developers often confuse HTML escaping (for HTML context) with JavaScript escaping (for JS string context). They might use `|safe` to avoid HTML entities (like `&quot;`) appearing in the string, not realizing this leaves the string vulnerable to quote injection. The correct filter is `|escapejs`, which escapes characters for JS string syntax but preserves the intended string content.
**Prevention:** Always use `|escapejs` (or `|json_script` / `json_encode`) when injecting data into JavaScript variables, regardless of whether the content is HTML or plain text. Never use `|safe` inside a script tag unless you are injecting trusted code (which is rare).
