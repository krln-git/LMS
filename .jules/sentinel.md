## 2024-05-18 - SQL Injection in Management Command via Unparameterized Insert
**Vulnerability:** A management command (`bulk_user_org_email_optout.py`) read rows from a user-supplied CSV and dynamically built a SQL `INSERT` statement by string formatting (`.format()`) rather than using proper SQL parameterization. If an organization name contained unescaped quotes (e.g., `org_name", "True", NOW(), NOW()); DROP TABLE users; --`), it would be executed directly as part of the query.
**Learning:** Even internal management scripts or scripts assumed to ingest "safe" files (like admin-provided CSVs) are vulnerable to SQL injection if input values are directly concatenated. It’s critical to use parameterized queries (`cursor.execute(query, params)`) for any external input. Bulk inserts can still be parameterized by constructing a single query string with multiple `%s` placeholders and extending a flat list of arguments.
**Prevention:** Always use `cursor.execute(query, [params])` when interpolating variables into raw SQL queries, regardless of the source of the data or the execution context (e.g. Django management commands). Never use python's string formatting (`%` or `.format()`) for SQL values.
